# ShoppingList

Лабораторная работа №5. Менеджер списка покупок (Model-View + делегат).

## Цель работы

Освоить архитектуру Model-View в Qt на практике: научиться отделять данные (`QStringListModel`) от их отображения (`QListView`), реализовать базовые операции CRUD (добавление, удаление, очистка) и создать кастомный делегат для редактирования элементов по двойному клику.

## Постановка задачи

Реализовать приложение **ShoppingList**:
1. Данные хранятся в `QStringListModel`, отображаются через `QListView`.
2. Кнопки «Добавить», «Удалить», «Очистить» управляют содержимым модели.
3. Кастомный делегат (`PurchaseDelegate`) позволяет редактировать элемент по двойному клику через встроенный `QLineEdit`.
4. Делегат корректно использует `save()` / `restore()` при рисовании, чтобы не портить соседние ячейки.

## Теоретическое обоснование 

**Model-View-Delegate (MVD).**
*   **Модель** (`QAbstractItemModel`, `QStringListModel`) — единственный источник истины о данных. Она не знает про пиксели, а только сообщает «что лежит в строке i» и шлёт сигналы (dataChanged, rowsInserted, rowsRemoved).
*   **Представление** (`QListView`) — как данные показаны (прокрутка, выделение). Оно не хранит данные, а запрашивает их у модели и слушается её сигналов.
*   **Делегат** (`QStyledItemDelegate`) — отвечает за конкретную ячейку: как её нарисовать (`paint`) и как редактировать (`createEditor` / `setModelData`).

**QModelIndex и роли.** Модель обращается к данным по индексу и роли:
*   `Qt::DisplayRole` — текст для отображения.
*   `Qt::EditRole` — значение для редактора.
*   `Qt::UserRole` — произвольные данные.

**save() / restore().** `QListView` переиспользует один `QPainter` для всех видимых ячеек. Если внутри `paint()` изменить перо или кисть и не восстановить, это «утечёт» на следующую ячейку. Поэтому любые изменения painter оборачиваются в `painter->save()` и `painter->restore()`.

**Граница Q_OBJECT.** Делегату `Q_OBJECT` не нужен (он только переопределяет виртуальные методы). Окну `MainWindow` он нужен, потому что там есть слоты кнопок.

## Почему Model-View, а не QListWidget

`QListWidget` смешивает данные и их отображение в одном месте. Это удобно для маленьких статичных списков, но ломается, когда нужно:
*   Отсортировать или отфильтровать данные (в Model-View это делает `QSortFilterProxyModel`, не трогая данные).
*   Показать те же данные в другом виде (одна модель → несколько view).
*   Кастомно отрисовать ячейку (в Model-View это делает делегат).

В нашем проекте данные лежат в `QStringListModel`, а `QListView` только отображает. Кнопки CRUD **изменяют модель**, а view обновляется автоматически по её сигналам.

## Разбор ошибок и их решений

**Ошибка 1. `multiple definition of ...`**
Компиляция прошла, линковка упала. Причина: `.cpp` файлы попали в сборку дважды (в `.pro` были указаны дубли). Решение: удалить дубли из `.pro`, удалить папку `build` и пересобрать.

**Ошибка 2. Редактор открывается в углу окна.**
Не переопределен метод `updateEditorGeometry()`. Решение: добавить `editor->setGeometry(option.rect);`.

**Ошибка 3. Отрисовка «течет» на соседние ячейки.**
Внутри `paint()` меняется состояние `QPainter` без восстановления. Решение: обернуть все изменения в `painter->save()` и `painter->restore()`.

## Вывод

В ходе работы изучена архитектура Model-View-Delegate. Освоено разделение данных (`QStringListModel`) и их представления (`QListView`). Реализованы CRUD-операции через модель (кнопки не трогают view напрямую). Создан кастомный делегат, который переопределяет `createEditor`, `setEditorData`, `setModelData`, `updateEditorGeometry` и `paint`. Понято, зачем нужен протокол `save()`/`restore()` в `paint()`: он защищает соседние ячейки от «утечки» состояния painter.

## Ответы на контрольные вопросы

**1. Как положить данные в список так, чтобы view их показал, не трогая сам view?**
Создать модель (`QStringListModel`), положить в неё данные через `setStringList()`, а затем привязать модель к view через `view->setModel(model)`. View сам запросит данные у модели и нарисует их.

**2. Как добавить новый элемент в список через модель?**
Вызвать `model->insertRow(row)` для создания пустой строки, затем `model->setData(model->index(row, 0), "текст", Qt::EditRole)` для записи текста. View обновится автоматически по сигналу `rowsInserted`.

**3. Как удалить выделенный элемент, работая с моделью, а не с items view?**
Получить текущий индекс: `QModelIndex current = view->currentIndex();`. Затем вызвать `model->removeRow(current.row());`. View обновится по сигналу `rowsRemoved`.

**4. Как очистить весь список одним вызовом модели?**
Вызвать `model->setStringList({});` (или `model->removeRows(0, model->rowCount());`). View очистится по сигналу `modelReset` или `rowsRemoved`.

**5. Как проверить, что изменение реально прошло через модель, а не через view?**
Посмотреть логи: если вы работаете через модель, в консоль выводятся сообщения вида `[CRUD] addItem: добавлено "Сыр"`. И view обновляется без ручных вызовов перерисовки (`update()`, `repaint()`). Это доказывает, что данные изменены в модели, а view лишь слушает её сигналы.

**6. Как включить редактирование ячейки строго по двойному клику?**
Вызвать `view->setEditTriggers(QAbstractItemView::DoubleClicked);`. По умолчанию там есть и другие триггеры (например, `EditKeyPressed`), их мы убираем, оставляя только двойной клик.

**7. Как повесить на список свой делегат?**
Создать экземпляр делегата (с родителем view, чтобы он удалился автоматически): `new PurchaseDelegate(view)` и вызвать `view->setItemDelegate(delegate)`.

**8. Как сделать, чтобы редактор при открытии показал текущий текст ячейки?**
Переопределить `setEditorData()` в делегате: взять `index.data(Qt::EditRole).toString()` и установить этот текст в редактор (например, `lineEdit->setText(value)`).

**9. Как сохранить введённое в редактор обратно в данные?**
Переопределить `setModelData()`: взять текст из редактора и вызвать `model->setData(index, newValue, Qt::EditRole)`. Важно писать в **модель**, а не в view.

**10. Как заставить редактор лечь ровно на ячейку, а не в угол окна?**
Переопределить `updateEditorGeometry()` и вызвать `editor->setGeometry(option.rect);`. `option.rect` — это прямоугольник ячейки в координатах view.

**11. Как в paint() делегата добавить свой рисунок, не сломав соседние ячейки?**
Обернуть все свои изменения `QPainter` в `painter->save()` (перед) и `painter->restore()` (после). Без этого изменённое перо или кисть «утекут» на следующую ячейку, и она нарисуется неправильно.

**12. Как объяснить, почему здесь Model-View, а не QListWidget?**
`QListWidget` смешивает данные и отображение. Model-View разделяет их: данные живут в модели, а view только показывает. Это позволяет сортировать, фильтровать, показывать те же данные в разных view и кастомно рисовать через делегат, не переписывая виджет.

**13. Как понять, нужен ли классу Q_OBJECT: делегату с только paint/createEditor – нужен, окну со слотами кнопок – нужен?**
`Q_OBJECT` нужен только для сигналов, слотов и свойств (`Q_PROPERTY`). Делегат переопределяет только виртуальные методы, поэтому `Q_OBJECT` ему не нужен. Окну `MainWindow` он **нужен**, потому что там есть слоты кнопок, подключённые через `connect`.
